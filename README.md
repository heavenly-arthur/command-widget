# Command Widget

Персональное офлайн-приложение для macOS с CLI-командами и шпаргалками для DevOps, Frontend, Backend и QA.

Command Widget живёт в строке меню и открывает плавающую панель, которую можно держать поверх остальных окон. Приложение предназначено для одного Mac и не требует аккаунта, интернета или API-ключей.

## Возможности

- 230 стартовых команд в 22 категориях;
- подробные локальные объяснения, теги и примеры запуска;
- поиск по названию, команде, категории, тегам и тексту справки;
- копирование команды в системный буфер обмена;
- сворачиваемые категории: при запуске все они закрыты;
- порядковые номера внутри категории;
- ручная сортировка команд перетаскиванием внутри категории с сохранением порядка;
- первоначальный выбор ролей DevOps, Frontend, Backend и QA и нужных CLI-категорий;
- 66 выбираемых подкатегорий инструментов: например PostgreSQL, MySQL, Redis, npm, Vite, Playwright и k6;
- вложенный каталог `категория → инструмент → команда`, где оба уровня можно сворачивать;
- повторная настройка ролей и категорий непосредственно в панели;
- плавающая панель, доступная во всех Spaces и рядом с полноэкранными приложениями.

## Быстрый запуск на другом Mac

Понадобятся macOS 14 или новее и бесплатные инструменты разработчика Apple. Если на Mac ещё нет Xcode или Command Line Tools, один раз выполните:

```zsh
xcode-select --install
```

Затем клонируйте репозиторий, соберите и откройте приложение:

```zsh
git clone https://github.com/heavenly-arthur/command-widget.git
cd command-widget
./scripts/build_app.sh release
open "build/Command Widget.app"
```

После запуска значок Command Widget появится в строке меню macOS. Обычной иконки в Dock у приложения нет — это штатное поведение.

Сборка создаётся и локально подписывается прямо на этом Mac, интернет для работы самого приложения не требуется. Готовый bundle находится в `build/Command Widget.app`. Его можно перенести в папку `Applications` через Finder.

Если macOS при первом открытии попросит подтверждение, откройте **Системные настройки → Конфиденциальность и безопасность** и нажмите **Открыть всё равно** для Command Widget.

## Повторная сборка

После получения изменений из GitHub:

```zsh
git pull --ff-only
./scripts/build_app.sh release
open "build/Command Widget.app"
```

Перед открытием новой сборки завершите уже запущенный Command Widget через его меню. Каталог пользователя при пересборке не удаляется и автоматически обновляется при следующем запуске.

Папка `build` намеренно не попадает в Git.

Для разработки и запуска тестов:

```zsh
swift test --disable-sandbox
```

## Данные

Каталог сохраняется в:

```text
~/Library/Application Support/CommandWidget/commands.json
```

Файл содержит версию схемы, встроенного каталога и пользовательский порядок. При обновлении приложения добавляются только новые встроенные записи; существующие изменения и порядок не перезаписываются. Повреждённый JSON не заменяется автоматически.

Выбранные роли и категории сохраняются отдельно в:

```text
~/Library/Application Support/CommandWidget/preferences.json
```

Первоначальная настройка открывается при первом запуске приложения. Позже выбор можно изменить кнопкой с ползунками в панели.

## Приватность

Приложение работает полностью локально:

- без сетевых запросов;
- без AI и внешних API;
- без телеметрии и аналитики;
- без аккаунтов и облачной синхронизации;
- без глобальных горячих клавиш.

## Структура

```text
Sources/CommandWidget/       интерфейс SwiftUI и AppKit-панель
Sources/CommandWidgetCore/   модель, локальное хранилище, поиск и порядок
  Catalogs/                  отдельный файл базы знаний для каждой категории
Tests/                       unit-тесты
docs/product/                scope, backlog и решения
docs/qa/                     отчёты проверок
scripts/build_app.sh         сборка персонального .app bundle
```
