## Текущая цель: первый локальный MVP

### CW-001 — Каркас приложения и плавающая панель

- Статус: `QA`
- Результат: приложение запускается из строки меню, показывает и скрывает панель, которая может оставаться поверх обычных окон.
- Не входит: глобальная горячая клавиша, автозапуск, WidgetKit.
- Acceptance criteria:
  1. После запуска в строке меню появляется элемент Command Widget, а обычная иконка в Dock не требуется.
  2. Пункт меню показывает панель и повторное действие скрывает её без завершения приложения.
  3. Панель остаётся выше обычных окон, присоединяется ко всем Spaces и допускается рядом с полноэкранным приложением.
  4. Панель можно перемещать, изменять её размер и закрывать стандартной кнопкой; повторное открытие продолжает работать.
  5. В меню есть явная команда завершения приложения.
  6. В исходниках нет регистрации глобальной горячей клавиши и сетевых/AI-зависимостей.
  7. Проект собирается на Mac владельца, а автоматические тесты контроллера панели проходят.

### CW-002 — Локальная модель и стартовый каталог

- Статус: `Done`
- Результат: локально доступны записи для Kubernetes, Helm, Flux, Linux, Ansible и Terraform; данные переживают перезапуск.
- Условие: стартовые записи не должны перезаписывать пользовательские изменения при следующем запуске.
- Acceptance criteria:
  1. Модель записи содержит ID, название, команду, категорию, теги, краткое и подробное описание, примеры и дату изменения.
  2. При первом запуске создаётся локальный JSON-каталог минимум с одной записью каждой из шести базовых категорий.
  3. Повторный запуск загружает существующий каталог и не восстанавливает удалённые или изменённые стартовые записи.
  4. Многострочные команды, Unicode, кавычки и обратные слэши сохраняются без искажений.
  5. Повреждённый файл возвращает понятную ошибку и не перезаписывается автоматически.
  6. Каталог отображается в панели без сети и сторонних зависимостей.
- QA: [2026-09-09-CW-002](../qa/2026-09-09-CW-002.md) — `PASS`.

### CW-003 — Просмотр, поиск и копирование

- Статус: `Done`
- Результат: пользователь фильтрует записи, открывает подробности и копирует точный текст команды.
- Acceptance criteria:
  1. Пустой запрос показывает весь каталог.
  2. Поиск регистронезависимо проверяет название, команду, категорию, теги, краткое и подробное описание.
  3. Запрос с пробелами по краям нормализуется, а отсутствие результатов показывает пустое состояние.
  4. Выбор записи открывает локальные подробности и примеры.
  5. Кнопка копирует точный текст команды в системный буфер и даёт визуальное подтверждение.
- QA: [2026-09-09-CW-003](../qa/2026-09-09-CW-003.md) — `PASS`.

### CW-006 — Расширенная база и пользовательский порядок

- Статус: `In Progress`
- Результат: содержательная офлайн-база с примерами организована в сворачиваемые категории, а порядок команд настраивается перетаскиванием и сохраняется.
- Acceptance criteria:
  1. В каталоге не менее 8 содержательных записей для каждой из шести категорий; у каждой есть объяснение и пример использования.
  2. Обновление существующей базы добавляет только новые bundled-записи, не перезаписывая изменённые записи и сохранённый порядок.
  3. При каждом запуске все категории свёрнуты; нажатие заголовка раскрывает или сворачивает категорию.
  4. Команды внутри категории имеют последовательную нумерацию.
  5. Команды можно перетаскивать внутри категории; новый порядок атомарно сохраняется в локальном JSON и восстанавливается после перезапуска.
  6. Во время активного поиска совпавшие категории раскрываются автоматически, а изменение порядка отключено во избежание неоднозначности.
  7. Ошибка сохранения показывается пользователю и не маскируется как успешное действие.

### CW-007 — Выбор ролей и категорий

- Статус: `QA`
- Результат: при первом запуске владелец выбирает профессиональные роли и CLI-категории, а затем может изменить выбор в панели.
- Границы: роли работают как локальные профили-рекомендации для существующих категорий; расширение базы новыми Frontend, Backend и QA-командами выполняется отдельными инкрементами.
- Acceptance criteria:
  1. При отсутствии файла настроек показывается обязательная первоначальная настройка с ролями DevOps, Frontend, Backend и QA.
  2. Выбор роли добавляет рекомендованные категории; снятие роли удаляет только её категории, не используемые другими выбранными ролями, после чего категории можно включать и выключать вручную.
  3. Нельзя завершить первоначальную настройку без хотя бы одной роли и одной категории.
  4. Основной каталог показывает только выбранные категории; поиск работает внутри выбранного набора.
  5. Настройку можно повторно открыть из панели, сохранить или отменить без изменения текущего выбора.
  6. Выбор атомарно сохраняется локально и восстанавливается после перезапуска.
  7. Настройки хранятся отдельно от каталога команд и не изменяют пользовательские записи или их порядок.
  8. Повреждённый файл настроек не перезаписывается автоматически; пользователь получает понятную ошибку.

### CW-008 — CLI-каталоги для Frontend, Backend и QA

- Статус: `QA`
- Результат: каждая роль предлагает собственный содержательный набор CLI-категорий, а обновление безопасно добавляет их в существующую локальную установку.
- Добавленные категории:
  - Frontend: Node.js, TypeScript, Frontend Tooling, Frontend Testing.
  - Backend: Python, Go, Databases, API & gRPC.
  - QA: API Testing, UI Testing, Load Testing, Mobile & Accessibility.
- Acceptance criteria:
  1. В каждой из 12 новых категорий есть не менее 8 команд с назначением, подробным объяснением и примером.
  2. Каждая новая категория входит в рекомендации соответствующей роли.
  3. Встроенный каталог содержит уникальные стабильные ID и увеличивает версию с 4 до 5.
  4. Обновление версии 4 добавляет ровно 96 новых записей и сохраняет изменённые пользователем команды и порядок.
  5. Старый файл настроек без номера версии декодируется; для выбранных ролей добавляются только новые рекомендованные категории версии 5.
  6. Ручной выбор старых категорий не удаляется миграцией.
  7. Приложение остаётся полностью локальным и не получает runtime-зависимостей от перечисленных CLI.

### CW-009 — Выбор подкатегорий и инструментов

- Статус: `QA`
- Результат: настройка использует иерархию `роль → категория → инструмент`, поэтому внутри широкой категории можно оставить только применяемые технологии.
- Acceptance criteria:
  1. Каждая из 22 категорий содержит хотя бы одну выбираемую подкатегорию; все 230 встроенных команд относятся ровно к одной подкатегории своей категории.
  2. В Databases отдельно выбираются PostgreSQL, MySQL, SQLite, Redis и MongoDB.
  3. Категория раскрывается и показывает вложенные подкатегории с отдельными флажками.
  4. Заголовок категории показывает состояния «ничего», «частично» и «выбрано всё», а также счётчик выбранных подкатегорий.
  5. Включение категории выбирает все её подкатегории; выключение снимает их все.
  6. Снятие последней подкатегории выключает родительскую категорию; снятие одной из нескольких оставляет категорию включённой.
  7. Выбор и снятие роли синхронно добавляет или удаляет подкатегории затронутых категорий, сохраняя общие категории других ролей.
  8. Каталог и поиск показывают только команды выбранных подкатегорий.
  9. Старый `preferences.json` без подкатегорий мигрирует без потери выбора: включаются все подкатегории ранее выбранных категорий.
  10. Подкатегории сохраняются только в настройках; `commands.json` и пользовательские записи не переписываются.
  11. Настройка занимает основную плавающую панель, имеет достаточную минимальную область списка и увеличивается вместе с изменением размера окна.
  12. Основной каталог отображает команды иерархически: категория → подкатегория → команда; каждый уровень независимо раскрывается и сворачивается.
  13. Поиск автоматически раскрывает только содержащие результаты категории и подкатегории.
  14. Перетаскивание меняет порядок команд только внутри выбранной подкатегории и не перемешивает соседние инструменты.
