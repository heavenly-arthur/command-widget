# Product and Architecture Decisions

## 2026-09-09 — Нативная плавающая панель вместо WidgetKit

Использовать SwiftUI для интерфейса и AppKit для управления плавающим окном. WidgetKit не подходит как основной интерфейс для полноценного поиска и CRUD.

## 2026-09-09 — Полностью локальная работа

Не использовать AI, внешние API, телеметрию, аккаунты и синхронизацию. Подробные объяснения входят в локальную модель записи.

## 2026-09-09 — Персональное приложение

Оптимизировать приложение для Mac владельца. Публикация, мультипользовательский режим и совместимость с другими платформами не входят в продуктовый scope.

## 2026-09-09 — Без глобальной горячей клавиши

Открывать панель через строку меню и обычные элементы интерфейса. Не регистрировать системные сочетания клавиш.

## 2026-09-09 — Версионированный локальный JSON-каталог

Хранить пользовательский каталог в `Application Support/CommandWidget/commands.json`. Файл содержит версию схемы и создаётся из стартового каталога только при отсутствии; существующий или повреждённый файл автоматически не перезаписывается.

## 2026-09-10 — Один исходный файл на категорию

Хранить Kubernetes, Helm, Flux, Linux, Ansible, Terraform, Ollama, CrowdSec, Mattermost и Git в отдельных файлах каталога. `StarterCatalog` только объединяет категории и создаёт стабильные ID. Это позволяет поручать наполнение независимым агентам с минимальными merge-конфликтами.

## 2026-09-12 — Роли как настраиваемые профили категорий

Хранить DevOps, Frontend, Backend и QA отдельно от категории команды. Роль предлагает набор существующих CLI-категорий, но пользователь может скорректировать его вручную. Выбор сохраняется в отдельном `preferences.json`, чтобы фильтрация интерфейса не меняла `commands.json` и не создавала риск потери пользовательских записей.

## 2026-09-12 — Ролевые каталоги как самостоятельные CLI-области

Добавлять Frontend, Backend и QA не одним общим разделом на роль, а самостоятельными категориями по назначению инструмента. Для версии 5 это четыре категории на роль и минимум восемь команд в каждой. Версия выбранных категорий хранится в настройках: при обновлении автоматически добавляются только новые категории выбранных ролей, а старый ручной выбор сохраняется.

## 2026-09-12 — Вычисляемая подкатегория вместо миграции команд

Использовать трёхуровневую таксономию `роль → категория → инструмент`. Подкатегория команды вычисляется локально из её категории, CLI и тегов, а выбор хранится в `preferences.json`. Не добавлять обязательное поле в `commands.json`: это позволяет классифицировать существующие пользовательские записи и не переписывать каталог при обновлении. Старые настройки без списка подкатегорий означают выбор всех инструментов внутри ранее выбранных категорий.

## 2026-09-12 — Настройки внутри resizable-панели

Показывать выбор ролей, категорий и инструментов поверх основного содержимого той же плавающей панели, а не в системном sheet. Панель открывается размером 900×700, имеет минимальный размер 700×560 и остаётся свободно изменяемой; список категорий занимает всё оставшееся пространство и прокручивается. Это устраняет тесный нересайзимый диалог при большой таксономии.
